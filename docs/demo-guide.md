## 推荐演示顺序（15~20 分钟）

### 第一步：登录认证演示（2 分钟）

```
使用 admin 登录 → 展示完整菜单 → 说明权限体系
```

**推荐话术：**

> "本项目基于 RBAC 权限模型，每个角色拥有不同的菜单和数据访问权限。admin 作为系统管理员，可以看到全部功能模块。"

### 第二步：RBAC 权限演示（3 分钟）

```
1. 退出 admin，使用 employee 登录
   → 仅显示工作台、知识库、采购申请
   → 无系统管理、无安全审计

2. 直接访问 /audit/login-logs
   → 跳转到 403 无权限页面
```

**推荐话术：**

> "employee 是普通员工角色，仅能查看知识库、提交采购申请。如果尝试访问无权限页面如安全审计，系统会自动拦截并显示 403 页面。前端的路由守卫和后端的 @SaCheckPermission 双重保障权限边界。"

### 第三步：系统管理演示（2 分钟）

```
使用 admin 登录：
1. 用户管理 → 浏览用户列表 → 点击详情
2. 角色管理 → 查看角色权限分配
3. 操作日志 → 筛选"用户管理"模块 → 查看刚才浏览记录
```

**推荐话术：**

> "所有管理类写操作都会被 @AuditLog 注解自动记录到操作日志表。管理员可以在操作日志中追溯每一次变更，包括操作人、操作模块、请求参数、执行耗时等。"

### 第四步：采购审批演示（4 分钟）

```
1. employee 登录 → 采购申请 → 新建申请
   - 金额填写 5000（部门审批级别）
   - 提交后状态变为"待审批"

2. dept_manager 登录 → 待办审批
   - 看到刚才的申请单 → 审批通过

3. admin 登录 → 查看操作日志
   - 筛选"采购管理"模块 → 看到申请和审批记录
```

**推荐话术：**

> "采购审批采用金额驱动多级审批流：一万以下部门负责人审批、一万到十万增加财务审批、十万以上触发采购管理员终审。每次审批操作都会记录到审计日志。"

### 第五步：知识库 RAG 演示（3 分钟）

```
1. admin 登录 → 知识库 → 文档管理
   - 上传一份 TXT 文件（如制度文档）
   - 等待状态变为"已就绪"

2. employee 登录 → 知识库 → 智能问答
   - 输入问题（与文档内容相关）
   - 查看回答和溯源引用
```

**推荐话术：**

> "知识库模块支持文档上传、自动解析、文本切分和基于关键词匹配的智能问答。每次回答都会附带溯源信息，展示引用了哪个文档的哪个片段。当前使用 mock embedding 和规则问答，未接入外部大模型 API。"

### 第六步：安全审计演示（3 分钟）

```
1. admin 登录 → 安全审计 → 安全看板
   - 查看今日登录统计、异常事件数

2. 安全告警 → 浏览告警列表
   - 查看自动生成的告警
   - 标记一条告警为"已处理"

3. 登录日志 → 筛选失败记录
   - 展示登录失败详情和失败原因
```

**推荐话术：**

> "安全审计增强模块对登录行为进行实时监控，自动检测异常登录、暴力破解等安全事件并生成告警。管理员可以在安全看板上一览系统安全态势，及时处理风险。"

### 第七步：操作日志追踪演示（2 分钟）

```
admin 登录 → 安全审计 → 操作日志
1. 筛选"用户管理"模块 → 查看用户操作历史
2. 筛选"采购管理"模块 → 查看采购操作历史
3. 点击详情 → 查看完整参数（密码字段已脱敏为"***"）
```

**推荐话术：**

> "操作日志 AOP 对所有管理类写操作进行自动记录，包括请求参数、执行结果、耗时等。敏感字段如密码、token 自动脱敏为星号，不会泄露到日志中。"

## 可选演示补充

### 错误密码演示

```
admin 登录 → 故意输入错误密码
→ 提示"用户名或密码错误"
→ 登录日志中出现 fail 记录，fail_reason="密码错误"
```

### 采购完整流程演示

```
employee 创建采购申请（金额 150000，触发三级审批）
→ dept_manager 审批通过
→ finance 审批通过
→ procurement 终审通过
→ 申请状态变为"已通过"
```

### 多角色快速切换

```
快速切换 admin / employee / auditor 三个账号，
展示不同角色的菜单和权限差异。
```
